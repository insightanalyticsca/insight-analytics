    On-demand SQL request sampling

    Parameterized DMV reads capture visible active requests. ScriptDom identifies syntactic INSERT target candidates; SQLite retains observations for search and export. This is best-effort sampling, not a complete audit or proof of committed changes.

    A single capture polls SQL Server or Managed Instance DMVs with existing permissions. ScriptDom analyzes visible current-statement SQL for INSERT target candidates, and SQLite stores repeated sampled observations with capture and successful-poll records. Operators inspect saved captures, search SQL and identity fields, filter flagged candidates, and export matching rows as CSV. Sampling can miss requests and never proves affected rows or commits.

    What the production app does

    • Start and stop one on-demand capture with a configurable delay after each poll.
    • Filter by current or original SQL login, host, database, application, session, and database user ID.
    • Parse visible current-statement INSERT syntax with ScriptDom and flag configured target candidates.
    • Search saved capture observations, inspect SQL and request metadata, and export matching rows as CSV.
    • Retain local capture history and mark unfinished captures interrupted after restart.
    • Treat observations as best-effort samples: requests can be missed, repeats are retained, and committed outcomes remain unknown.
